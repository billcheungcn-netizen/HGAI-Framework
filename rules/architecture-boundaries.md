# 架构边界规则

- 保持模块化、单向依赖、高内聚和低耦合；
- 一个业务职责只有一个权威实现；
- 展示层不得复制或承担领域逻辑；
- 禁止跨模块直接访问内部实现；
- 禁止为单个需求破坏整体依赖方向；
- 禁止未经批准的兜底、兼容、双写和第二套实现；
- 优先修复根因，不用局部补丁隐藏结构问题；
- 实际结构与 `ARCHITECTURE.md` 或 `MODULE_MAP.md` 不一致时暂停并调查；
- 新需求使定位路径变长时，评估模块地图或架构是否需要重构。

出现重复逻辑、循环依赖、职责无法解释、AI 多次找错模块或小需求需要扫描大量无关代码时，停止继续堆功能并建立架构审计。
