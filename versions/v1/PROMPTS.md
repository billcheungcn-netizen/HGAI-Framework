# 可复用 AI 开发提示

以下提示与项目根目录的 `AGENTS.md` 配合使用。

## 1. 新需求：先定位和计划

```text
先完整阅读项目根目录的 AGENTS.md，并根据其中的索引查找与本需求相关的历史文档、架构说明和模块地图。

本次需求：<粘贴需求>

现在不要修改代码。请先：
1. 复述你对需求的理解；
2. 指出责任模块、目标目录、目标文件和主要调用入口；
3. 列出你实际阅读过的文档和代码；
4. 说明哪些模块和文件不应修改；
5. 检查单向依赖、高内聚低耦合和业务边界；
6. 明确禁止采用的兜底、兼容、重复实现或跨模块方案；
7. 创建任务文档，写出文件级执行计划和验证方法。

如果无法精确定位，继续调查，不要用全仓盲目修改代替定位。
```

## 2. 批准计划后执行

```text
按照已批准的任务文档执行，不得擅自扩大范围。

执行要求：
- 只修改计划列出的责任模块；
- 优先修复根因，不增加未经批准的兜底或兼容；
- 不创建第二套平行实现；
- 实际情况与计划不符时立即暂停，更新文档并说明偏差；
- 完成后执行验收、测试、构建和架构检查；
- 在任务文档中记录实际修改、验证结果和遗留问题；
- 更新 AGENTS.md 的文档索引。
```

## 3. Bug：先复现和定位根因

```text
先阅读 AGENTS.md 和相关历史 Bug 文档。

问题现象：<粘贴问题>

不要直接修代码。先完成：
1. 写出稳定复现方法；
2. 收集日志、错误和调用链证据；
3. 区分表面症状与根因；
4. 确认责任模块和具体文件；
5. 检查是否已有兜底、兼容或重复逻辑掩盖问题；
6. 创建 Bug 文档并给出修复计划；
7. 设计修复前会失败、修复后会通过的验证。

禁止通过吞掉错误、添加默认值或复制另一套逻辑来假装问题已解决。
```

## 4. 审核 AI 的开发计划

```text
请重新审核这份开发计划，不要默认它是正确的。

重点检查：
- 是否误解了原始需求；
- 是否选错模块、目录或文件；
- 是否违反单向依赖或业务边界；
- 是否准备增加兜底、兼容、重复逻辑或平行实现；
- 是否修改了与需求无关的范围；
- 验收方法能否真正证明需求完成；
- 是否遗漏了 AGENTS.md 中的相关历史文档。

输出明确的通过项、问题项和需要修订的计划。此阶段不要修改代码。
```

## 5. 架构审计和重构

```text
先阅读 AGENTS.md、ARCHITECTURE.md、MODULE_MAP.md 和相关历史重构文档。

对 <模块或范围> 进行架构审计，检查：
- 模块职责是否清晰；
- 依赖是否单向；
- 是否存在循环依赖；
- 是否有重复实现、跨层调用、兜底堆积或长期兼容；
- 是否因结构混乱导致 AI 每次读取大量无关代码；
- 文档、索引和真实代码是否一致。

先创建架构审计文档，提出目标结构和可分步验证的重构计划。重构的目标是删除混乱和缩短认知路径，不是再增加一层包装。
```

## 6. 次日或新会话恢复

```text
先完整阅读 AGENTS.md、当前任务文档和最新 handoff 文档。

在修改任何文件前，请回答：
1. 当前目标是什么；
2. 已经完成了什么；
3. 下一步是什么；
4. 责任模块和目标文件是什么；
5. 哪些方向已经证明错误；
6. 哪些模块和方案明确禁止；
7. 最近一次验证结果是什么。

只有在上述内容与文档一致后才能继续执行。
```
