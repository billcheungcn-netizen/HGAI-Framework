# AI 开发每日执行清单 V2

> 默认使用轻量清单。内容由 AI 执行和记录，人只审核标有“人审”的项目。

## 快速模式：日常默认

- [ ] **AI** 已读 `AGENTS.md`、适用规则、术语表和相关历史
- [ ] **人审** 已用终端用户语言确认功能、需求、使用方式和可见变化
- [ ] **AI** 已通过模块地图定位责任模块、文件和禁止范围
- [ ] **人审** 责任模块、负面约束和验收结果方向正确
- [ ] **工具** 已记录 Git 基线并保护用户未提交修改
- [ ] **AI** 功能代码与新增或更新的自动化测试同批完成
- [ ] **工具** 用户流程、测试、构建和必要检查已真实执行
- [ ] **工具** 已按授权建立引用任务 ID 的 Git 检查点
- [ ] **AI** 已更新权威文档、索引、术语和必要规则
- [ ] **AI** 已用“功能—需求—使用—变化—收益—验收”向项目负责人反馈

## 严格或重构模式：额外检查

- [ ] **人审** 非目标、跨模块影响、依赖和权限风险已确认
- [ ] **工具** 已使用独立分支或其他安全隔离方式
- [ ] **AI** 每个阶段都有可独立验证和回退的检查点
- [ ] **人审** 新依赖、许可证、密钥、数据迁移或兼容策略已批准
- [ ] **工具** 相关回归、架构检查和密钥/依赖审计已执行
- [ ] **AI** 旧实现、临时兜底和无期限兼容已按计划清理

## 立即暂停堆功能的信号

- AI 多次找错模块；
- 小任务需要扫描大量无关代码；
- 同一职责出现多个实现；
- 兜底、兼容或双写持续增加；
- 模块出现反向或循环依赖；
- 文档、规则、测试和代码相互矛盾；
- 主索引持续膨胀，过期文档仍被加载；
- 无法向项目负责人清楚说明终端用户究竟获得了什么。

出现任一项，应先建立架构、文档或规则审计，再继续增加功能。
