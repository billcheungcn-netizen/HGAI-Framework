# 依赖与密钥治理规则

## 第三方依赖

未经批准不得引入新依赖。申请新依赖时必须说明：

- 现有依赖或标准库为什么无法完成；
- 包名、用途和固定版本；
- 维护状态和可信来源；
- 许可证是否与项目兼容；
- 权限、网络、构建体积和供应链风险；
- 替代方案；
- 锁文件变化。

不得仅因为“实现更方便”就引入大型依赖。

## 密钥与凭据

API Key、Token、密码、私钥、OAuth 凭据、初始化密码和会话数据不得写入：

- 源代码；
- 测试数据；
- 日志；
- 任务、Bug、交接和架构文档；
- `AGENTS.md` 或规则文件；
- 聊天消息；
- Git 历史。

使用环境变量名或安全存储引用，不写真实值。发现疑似密钥时立即停止，不在输出中复述内容，并报告位置和处理建议。

## 验证

- 检查依赖清单和锁文件；
- 检查是否新增网络访问或权限；
- 运行项目已有的密钥扫描和依赖审计；
- 没有现成工具时，在任务文档记录缺口并建立治理任务。
