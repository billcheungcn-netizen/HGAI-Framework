# Git 证据链与回退规则

## 开始任务前

- 记录当前分支、HEAD Commit 和工作区状态；
- 识别并保护用户尚未提交的修改；
- 记录项目授予 AI 的 Git 权限；
- 高风险任务先建立可验证的干净基线；
- 重构、新模块和跨模块任务使用独立分支。

## 任务与 Commit 关联

- 每个任务有稳定任务 ID；
- Commit message 必须引用任务 ID；
- 小任务可以一任务一 Commit；
- 大任务按已验证检查点拆分多个 Commit；
- 一个 Commit 不混入无关任务；
- 功能代码、对应测试和必要文档处于同一证据链；
- 任务文档记录实际 Commit ID。

建议格式：

```text
[TASK-20260829-001] 完成用户登录保持功能
[BUG-20260829-002] 修复重复提交订单
```

## 回退

- 共享历史优先使用 `git revert`；
- 未共享任务分支的历史重写必须获得明确授权；
- 不得覆盖未提交的用户修改；
- 不得把“手动把代码改回去”当作可靠回滚；
- 回退后重新执行与基线相同的验证；
- 回退原因和结果写入任务文档。

## 禁止

- 未经授权不得提交、推送、合并或改写历史；
- 禁止把密钥、生成物、缓存或无关改动加入 Commit；
- 禁止为了得到干净状态而丢弃未知来源的修改；
- 禁止在测试失败时创建“完成”Commit。
